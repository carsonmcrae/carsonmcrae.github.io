Where it stands

In use, with room to learn.

Recalen is in an ongoing private beta with 20+ testers. Several use it daily. I am keeping this stage focused on whether capturing something now makes it easier to retrieve and use later.

Usage figures are reported by me. Public release remains ahead; the roadmap does not commit to a launch date.

Scope

Own the whole capture-and-recall loop.

I built quick entries, longer Notes, organization, search, reminders, selected email forwarding, and account controls across responsive web and native mobile. Each feature needs to fit that loop.

For native offline use, I deliberately limited writes to new personal captures and made downloaded-content access explicit. Editing everything offline would require a much broader set of conflict decisions.

Sequencing

Three different reasons to do the next piece of work.

I established the web product and API boundary before expanding native capability. Shared product rules and contracts keep behavior connected while the interfaces adapt to each platform.

Dependencies

A feature can be built before the release is ready.

Sign-in, storage, email, processing, and notifications need to work together. I keep implementation, connected integrations, and release verification as separate milestones so that an available code path does not stand in for a working user journey.

  • Verify connected workflows in the environment people will use.
  • Check interruption and recovery alongside the successful path.
  • Review accessibility on the affected surfaces.
  • Verify native behavior on a physical device before calling it certified.
  • Confirm data recovery and support readiness before widening access.

These are release criteria. This snapshot does not assert that every criterion has passed.

Decision record

Make the tradeoff visible.

I record durable decisions so the reason survives the implementation: corrections should outlast another organization pass; a reminder should stay with its plan step; and offline capture should preserve a thought without pretending the entire account is on the device.

The public board summarizes those foundations alongside current validation and future conditions. It began on October 19, 2026; implemented cards are examples of existing work, rather than a reconstructed history of how this board was used.
